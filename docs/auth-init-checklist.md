# 认证初始化执行清单

> 当前文档已从“待执行清单”切换为“阶段完成情况 + 后续行动清单”，用于说明认证初始化阶段哪些内容已经落地，哪些仍留给后续迭代。

## 1. 当前结论

截至 2026-06-01，认证初始化阶段已经完成最小闭环：

1. 前端登录页已可用
2. Token 存储与恢复链路已可用
3. 路由登录态守卫已可用
4. `POST /api/auth/login` 已可用
5. `GET /api/auth/me` 已可用
6. `POST /api/auth/logout` 已可用
7. `GET /api/auth/menus` 已可用
8. 前后端 Docker 联调已通过
9. APIFox 调试链路已通过

一句话总结：

`认证初始化阶段已经不再是规划态，而是已进入“可支撑 RBAC 业务继续开发”的完成态。`

## 2. 已完成项

### 2.1 后端

已完成：

1. 新增认证模块 `backend/src/modules/auth/`
2. 新增 JWT 工具与鉴权中间件
3. 实现账号密码登录
4. 实现 `/api/auth/login`
5. 实现 `/api/auth/me`
6. 实现 `/api/auth/logout`
7. 实现 `/api/auth/menus`
8. 实现基于角色权限的菜单过滤
9. 为菜单组树与路径映射补充最小单元测试

### 2.2 前端

已完成：

1. 新增 `/login` 路由与登录页
2. 新增 `auth store`
3. 接入 Token 存储与恢复
4. 接入登录态路由守卫
5. 顶栏已接入当前用户展示与退出登录
6. 菜单已从统一数据源初始化
7. 登录后可进入控制台
8. 刷新后可恢复登录态与菜单

### 2.3 调试与联调

已完成：

1. Docker 下 `postgres + backend + frontend` 联调通过
2. OpenAPI 文件已补齐认证与菜单接口
3. APIFox 调试说明已补齐
4. APIFox 前置/后置脚本已补齐
5. `admin`、`sysadmin`、`auditor` 三类账号已完成菜单裁剪验证

## 3. 当前阶段验收结果

当前已满足：

1. 可以通过账号密码登录
2. 登录成功后可进入控制台
3. 刷新页面后登录态仍能恢复
4. 未登录访问后台页会被重定向到 `/login`
5. 已登录访问 `/login` 会回到控制台
6. `/api/auth/me` 返回用户、角色、权限
7. `/api/auth/menus` 返回当前用户可见菜单树
8. 退出登录后无法继续访问受保护页面

## 4. 当前阶段未纳入内容

下面这些仍然不属于当前认证初始化完成范围：

1. Refresh Token
2. 图形验证码
3. 登录失败次数限制
4. 密码过期与安全策略
5. 多租户真实登录上下文
6. 按钮级权限指令
7. 后端接口级细粒度权限校验

## 5. 建议保留的测试关注点

虽然本阶段已完成，但后续迭代仍建议保留这些回归点：

1. 错误用户名登录
2. 错误密码登录
3. 禁用用户登录
4. 非法 Token 访问 `/api/auth/me`
5. 非法 Token 访问 `/api/auth/menus`
6. 刷新后登录态恢复
7. 不同角色菜单裁剪差异

## 6. 现在最自然的下一步

认证初始化阶段完成后，建议不再继续扩它本身，而是进入 RBAC 业务接口阶段。

推荐顺序：

1. 用户管理接口设计与占位实现
2. 角色管理接口设计与占位实现
3. 菜单管理接口设计与占位实现
4. 再逐步补权限点、分页查询和统一列表筛选结构

一句话原则：

`认证主链路已经打通，下一步应从“我是谁、我能看到什么”进入“我如何管理系统对象”。`
