# 前端认证接入 TODO 清单

本文档用于承接当前已经完成的后端认证初始化成果，整理前端接入认证主链路时的执行清单，方便后续按步骤落地、评审和迭代。

## 1. 目标

本阶段目标不是做完整 RBAC 动态权限，而是先让前端具备稳定的登录态能力。

当前阶段前端认证接入的核心目标：

1. 提供登录页
2. 接入后端登录接口
3. 保存 Access Token
4. 初始化当前用户信息
5. 接入路由登录态守卫
6. 支持退出登录

一句话总结：

`先让前端知道“谁已经登录”，再继续接菜单、权限和用户中心。`

## 2. TODO 清单

### 2.1 登录页

1. 新增 `/login` 路由
2. 新增登录页组件
3. 提供 `username` 和 `password` 表单项
4. 增加基础输入校验
5. 增加登录按钮加载态
6. 增加登录失败提示

### 2.2 Auth Store

1. 新增 `auth store`
2. 保存 `access_token`
3. 保存当前用户基础信息
4. 保存角色列表
5. 保存权限列表
6. 提供 `login`
7. 提供 `fetchMe`
8. 提供 `logout`
9. 提供 `clearAuth`

### 2.3 Token 工具

1. 新增 Token 存取工具
2. 提供 `getToken`
3. 提供 `setToken`
4. 提供 `removeToken`
5. 统一本地持久化方式
6. 第一阶段建议使用 `localStorage`

### 2.4 请求层鉴权

1. Axios 请求自动附带 `Authorization: Bearer <token>`
2. 统一处理 `401`
3. Token 失效后清空登录态
4. 为后续刷新 token 逻辑预留扩展点

### 2.5 登录接口接入

1. 接入 `POST /api/auth/login`
2. 登录成功后保存 token
3. 保存登录响应中的用户基础信息
4. 登录成功后跳转控制台首页

### 2.6 当前用户接口接入

1. 接入 `GET /api/auth/me`
2. 页面初始化时拉取当前用户信息
3. 更新角色与权限状态
4. 为后续菜单树和权限控制预留数据入口

### 2.7 路由守卫

1. 未登录访问后台页时跳转 `/login`
2. 已登录访问 `/login` 时跳转 `/dashboard`
3. 刷新页面时尝试恢复登录态
4. token 存在但用户信息为空时调用 `/api/auth/me`

### 2.8 退出登录

1. 接入 `POST /api/auth/logout`
2. 退出后清空本地登录态
3. 跳转登录页
4. 如果退出接口失败，前端仍应清理本地状态

### 2.9 顶栏信息接入

1. 顶栏展示当前用户昵称或用户名
2. 增加退出登录入口
3. 预留后续租户、角色展示位

### 2.10 初始化与边界处理

1. 应用启动时检查本地 token
2. 避免刷新后丢失当前用户上下文
3. 避免路由守卫与页面初始化重复请求
4. `/me` 请求失败时自动回登录页
5. token 被撤销或过期时自动清空状态

## 3. 推荐实施顺序

建议按下面顺序推进：

1. 新增登录页与 `/login` 路由
2. 新增 `auth store`
3. 新增 token 工具
4. 接入 `POST /api/auth/login`
5. 接入 `GET /api/auth/me`
6. 增加路由守卫
7. 接入退出登录
8. 顶栏展示当前用户信息

## 4. 推荐文件落点

建议优先使用下面的文件结构：

```text
frontend/src/
├─ views/auth/
│  └─ LoginView.vue
├─ stores/
│  └─ auth.ts
├─ api/
│  └─ auth.ts
├─ utils/
│  └─ auth.ts
└─ router/
   └─ index.ts
```

说明：

1. `views/auth/` 用于登录页
2. `stores/auth.ts` 用于统一登录态状态管理
3. `api/auth.ts` 用于封装认证接口
4. `utils/auth.ts` 用于封装 token 存储工具
5. `router/index.ts` 用于接入登录态守卫

## 5. 当前阶段完成标准

当下面条件满足时，可认为前端认证接入阶段完成：

1. 可以通过登录页输入账号密码登录
2. 登录成功后进入控制台
3. 页面刷新后登录态仍可恢复
4. 未登录访问后台页会跳转到 `/login`
5. 已登录访问 `/login` 会跳转回后台首页
6. 顶栏可以展示当前用户基础信息
7. 点击退出登录后无法继续访问后台页

## 6. 后续衔接建议

当前阶段完成后，后续最自然的推进顺序是：

1. 接入动态菜单初始化
2. 接入权限标识控制
3. 接入按钮权限指令
4. 再进入用户、角色、菜单管理页面开发

一句话原则：

`先建立稳定登录态，再让 RBAC 页面真正依赖这条认证主链路。`
